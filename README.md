# LLM2Everything 仕様メモ

Windows 用の日本語ファイル検索アプリです。自然な日本語の検索指示を、まず高速ルールで検索条件へ変換し、確定できない場合だけ Ollama による LLM 変換を試みます。実際のファイル検索は Everything / es.exe を利用します。

## 目的

- 日本語の曖昧な入力から、Everything で実行可能な検索式を作る。
- 日付、サイズ、拡張子、ファイル種別、ドライブ、除外語を扱う。
- Everything の結果に対して、必要に応じてアプリ側でも日付とサイズを再フィルターする。
- 検索履歴と変換キャッシュを保存し、同じ検索を素早く再実行できるようにする。

## 実行環境

- OS: Windows
- UI: WPF
- Target Framework: .NET 10
- 検索エンジン: Everything
- CLI 検索: es.exe
- LLM 変換: Ollama

## プロジェクト構成

- `LLM2Everything.App`
  - WPF UI、検索実行フロー、設定画面、履歴操作。
- `LLM2Everything.Core`
  - 検索意図モデル、高速ルール、日時解釈、Everything 検索式生成、バリデーション。
- `LLM2Everything.Infrastructure`
  - es.exe 実行、Everything 検出、Ollama 通信、JSON 保存、ログ。
- `LLM2Everything.Tests`
  - 重要な変換、日時、検索式、保存処理の回帰テスト。

## 検索フロー

1. ユーザーが検索文を入力する。
2. 対象フォルダー、種別指定、ファイルタイプ、拡張子指定があれば入力条件へ加える。
3. 高速ルールで検索意図を作る。
4. 高速ルールで曖昧な場合だけ Ollama へ問い合わせる。
5. 検索意図を Everything 表示用検索式に変換する。
6. 日付またはサイズ条件がある場合、es.exe に渡す実行用検索式から `dm:` と `size:` を外す。
7. es.exe から `更新日時` と `サイズ` を取得する。
8. アプリ側で日付とサイズを厳密にフィルターする。
9. 結果、履歴、変換詳細を UI に表示する。

## UI 仕様

### メイン画面

- 上部に警告バーを表示する。
  - `es.exe` 未設定時に警告。
  - Ollama 未接続時に警告。ただし高速ルールで確定できる検索は継続可能。
- 検索入力欄で Enter または検索ボタンを押すと検索する。
- キャンセルボタンで現在の検索を中断する。
- 設定ボタンで設定画面を開く。
- 変換詳細を表示/非表示できる。
- 変換詳細には表示用 Everything 検索式と JSON 詳細を表示する。
- 検索結果はダブルクリックでファイルを開く。
- 検索結果の右クリックメニュー:
  - 開く
  - エクスプローラーで選択
  - フルパスをコピー
- 検索結果の列ヘッダークリックでソートする。

### 対象フォルダー

- 空欄の場合は Everything 側の全インデックス対象。
- 入力がある場合のみフォルダーに限定する。
- 複数フォルダーは `;` 区切り。
- 存在しないフォルダーが含まれる場合は検索を実行しない。

### 履歴

- 検索履歴は最大 20 件。
- 履歴は ListView で表示する。
- 履歴の再検索ボタンで選択履歴を再検索する。
- 履歴行のダブルクリックでも同じ再検索を実行する。
- 削除ボタンで選択履歴を削除する。

## 高速ルール仕様

### ファイル種別と拡張子

- ファイルタイプ名が入力文に含まれる場合、そのファイルタイプの拡張子を対象にする。
- 既知拡張子が入力文に含まれる場合、その拡張子を対象にする。
- 代表的な別名:
  - エクセル / excel / xlsx / xls / 表計算 / ワークシート
  - ワード / word
  - パワポ / パワーポイント / powerpoint

### ビジネス文書名の揺らぎ

ファイル名検索用に、以下の同義語グループを OR 条件にする。

- 請求書: 請求書, 請求, invoice, インボイス
- 見積書: 見積書, 見積もり書, 見積り書, 見積もり, 見積り, 見積, 御見積, quotation, quote
- NDA: NDA, 秘密保持契約, 機密保持契約, 秘密保持, 機密保持, non-disclosure, nondisclosure
- 契約書: 契約書, 契約, agreement, contract
- 注文書/発注書: 注文書, 発注書, 注文, 発注, purchase order, po
- 納品書: 納品書, 納品, delivery note
- 領収書: 領収書, 領収, receipt
- 申込書: 申込書, 申込み書, 申し込み書, 申込, 申込み, application
- 提案書: 提案書, 提案, proposal
- 仕様書: 仕様書, 仕様, spec, specification

### 日付

JST を基準に解釈する。

- 今日
- 昨日
- 今週
- 先週
- 今週月曜日から今週日曜日
- 先週月曜日から先週日曜日
- 過去 N 日
- 過去 N 時間
- N日

例:

- `昨日のエクセル`
- `17日のxlsx`
- `先週月曜日の10GB以上のgguf`

### サイズ

- `KB`, `MB`, `GB`, `TB`, `B` を解釈する。
- `以上` は最小サイズ。
- `以下` と `未満` は最大サイズ。
- 演算は 1024 ベース。

例:

- `1GB以上のZIP`
- `10GB以上のgguf`

### ドライブ

- `Eドライブ` のような指定を `E:\` に変換する。

### 除外語と包含語

- `releaseを除く` のような表現を除外語にする。
- `名前を含む` / `ファイル名に...を含む` 系の表現を包含語にする。

## Everything 検索式

- 表示用検索式には日付条件とサイズ条件を含める。
- 実行用検索式では、日付条件とサイズ条件を外す場合がある。
- 理由:
  - Everything の `dm:` や `size:` の解釈差で漏れや混入が起きるのを避けるため。
  - es.exe で広めに取得し、アプリ側で `ModifiedAt` と `SizeBytes` を比較する。

## es.exe 実行仕様

- `-dm`
- `-size`
- `-date-format 1`
- 必要に応じて `-sort-date-modified-descending`
- 結果上限は設定値を使う。
- アプリ側フィルターがある場合、内部取得件数は最低 10000 件まで広げる。
- es.exe 出力は CP932 として読む。
- 日本語パス、空白パス、サイズ付き出力をパースする。

## 保存仕様

保存先は `%LOCALAPPDATA%\LLM2Everything`。環境変数 `LLM2EVERYTHING_DATA_DIR` がある場合はそれを優先する。

- 設定
- 履歴
- 変換キャッシュ
- ファイルタイプ定義
- ログ

JSON は原子的に保存する。破損時はバックアップから復旧する。

## キャッシュ仕様

- 変換キャッシュは最大 100 件。
- キャッシュキーには次を含める。
  - 入力文
  - 対象フォルダー
  - ファイル種別指定
  - 拡張子指定
  - タイムゾーン
  - プロンプト/ルールバージョン
  - モデル名
- 相対日付を含む検索は JST 日付キーも保存する。
- 現在のルールバージョンは `search-intent-v3`。

## 現時点の制限

- ファイル本文検索は未実装。
- 「請求書」「NDA」などはファイル名ベースの揺らぎ検索。
- フォルダー指定 UI はシンプルなテキスト入力。
- 高速ルールで確定できない表現は Ollama が必要。
- 手動検索式の再検索では、検索意図が無いのでアプリ側の日付/サイズフィルターは働かない。
